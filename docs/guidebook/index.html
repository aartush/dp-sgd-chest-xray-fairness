01Overview

Differential privacy is the standard guarantee for training models on sensitive medical images. DP-SGD is the mechanism most often used to deliver it. This project asks a question that aggregate accuracy hides: who pays for that guarantee?

One-sentence result. The privacy guarantee is real and measurable — membership-inference AUC falls from 0.634 without DP to 0.596 at ε = 1 — while a class-weighted loss is a free, consistent partial remedy for the minority class, and a pretrained initialisation, despite being the best arm without DP, backfires under noise.

What is in this guidebook

Everything needed to understand, run, audit and present the project: the research question and the two papers it responds to, the dataset and its imbalance, the full method (including the DP-SGD guarantees and how they were achieved), the results with their uncertainty, the exact software versions, how to reproduce every number, and how to run the live version.

02The research question

DP-SGD clips every per-example gradient to a fixed norm before averaging and adding noise. That clipping is what bounds any single patient's influence on the released model — it is the guarantee. But it also discards the update from examples whose gradients are largest, and in an imbalanced clinical dataset those are disproportionately the minority class.

Does DP-SGD degrade recall for minority classes disproportionately — and can cheap, privacy-neutral interventions (a class-weighted loss, a pretrained initialisation) recover that loss without weakening the guarantee?

Why accuracy cannot answer it

PneumoniaMNIST's test split is 26% normal / 74% pneumonia. A model that predicts "pneumonia" for every scan scores 74% accuracy while achieving zero recall on the normal class. Accuracy is blind to exactly the harm this project measures, so the primary metric is minority-class (normal) recall and the majority–minority recall gap.

03The two papers and the gap

Paper 1 — Huang & Xie, arXiv:2507.06619 (9 July 2025)

"Steps Adaptive Decay DPSGD: Enhancing Performance on Imbalanced Datasets with Differential Privacy with HAM10000." The abstract states that gradient-noise DP methods "work well on large datasets like MNIST and CIFAR-100, but fail on small, imbalanced medical datasets like HAM10000," attributing the failure to minority-class gradients being clipped while majority classes dominate the update. Their remedy changes the training schedule — linearly decaying the noise and clipping thresholds — and reports a 2.15% accuracy gain at ε = 3, δ = 1e-3 over an Auto-DPSGD baseline.

Gap. Only aggregate accuracy is reported, so the paper cannot show whether the minority class was fixed or simply swamped. No loss-level or initialisation intervention is tested. It is a two-author arXiv preprint with no peer review and no attack-based privacy evaluation.

Paper 2 — Mohammadi et al., arXiv:2506.00660 (31 May 2025) → npj Digital Medicine 9:93 (2026)

"Differential privacy for medical deep learning: methods, tradeoffs, and deployment implications." A scoping review of 74 studies published through March 2025. It concludes that "severe degradation often occurs under strict privacy (ε ≈ 1), particularly in underrepresented or complex modalities"; that "privacy-induced performance gaps disproportionately affect demographic subgroups"; and that only a small subset of studies evaluates these tradeoffs. The abstract names "balancing privacy with utility and fairness" as a critical challenge.

Gap. A review can identify the tension but cannot test a remedy. No study in it isolates minority-class recall as the outcome, and none tests whether a one-line loss change closes the gap.

This project's contribution. Hold the DP mechanism fixed and vary only the loss (class weights) and the initialisation (ImageNet transfer). Report per-class recall and a membership-inference attack at matched ε. Both interventions use public information only, so neither consumes privacy budget — any recovery is genuinely free at the same ε.

Citation note. Both were verified against arXiv, Crossref and Europe PMC, not assumed. The review's DOI string contains "2025" but the journal version's publication year is 2026 — cite accordingly.

The minority class is "normal". That is the clinically meaningful direction for screening: a normal scan misread as pneumonia triggers unnecessary follow-up, and in a screening setting that is the costly error. The test split is less imbalanced than train (37% vs 26% normal), which matters for the attack: a pooled membership-inference AUC would partly measure the distribution shift rather than memorisation, so the primary privacy number is class-conditional.

ChestMNIST (scale check)

78,468 frontal X-rays, 14 multi-label findings from NIH-ChestXray14; the rarest label has only 144 positives in the full training set (0.18%). Capped at 8,000 training images for tractability, and labelled as such everywhere it appears. It is a transfer check, not a replication.

Both datasets are public and de-identified, download automatically through the medmnist package, and require no data-use agreement.

05Method

DP-SGD in one paragraph

For a batch of size B, per-example gradients gᵢ are clipped to norm C (g̃ᵢ = gᵢ · min(1, C/‖gᵢ‖)), summed, and perturbed with Gaussian noise:

θ ← θ − η · ( Σᵢ g̃ᵢ + σ·C·N(0, I) ) / B

The accountant converts (σ, sample rate, number of steps) into an (ε, δ) guarantee. This project fixes δ = 1e-5, plans a step budget, solves for the σ that spends exactly the target ε over that budget, then records the achieved ε per run. Every arm uses the same batch size and data order, so ε is the only variable distinguishing private runs.

Why these two interventions are privacy-neutral

Class weights are computed from the training label histogram — public aggregate information — and the accountant never sees them. ImageNet weights are public. Neither consumes privacy budget, so any recovery they produce is genuinely free at the same ε. That is the practical claim of the project.

The model, and the constraints Opacus imposes

ResNet-18 adapted to 1×28×28 input. Three changes are required, not stylistic:

  • GroupNorm replaces every BatchNorm. Opacus cannot form per-sample gradients through batch statistics and rejects such models outright — there is a negative-control test asserting this failure.
  • ReLU is non-in-place. Opacus' backward hooks return views that autograd forbids from being mutated in place.
  • The residual block's out += identity is replaced with an out-of-place add, for the same reason.

Clipping bound calibration

C is set from the median true per-sample gradient norm, measured once on an untrained model using Opacus' own grad_sample buffers. The median (not max) keeps clipping noise low. The statistic is aggregated, computed before training, and releases nothing per example.

Membership-inference attacks

Primary — loss threshold (Yeom-style). Score each example by −cross-entropy loss; low loss implies membership; compute ROC-AUC over members (train) vs non-members (test). Reported class-conditionally (within each class, then averaged) to remove the train/test class-mix confound. An AUC of 0.5 means the attack cannot distinguish members from non-members at all.

Secondary — shadow model. A logistic-regression attacker trained on a separate model's in/out behaviour over (loss, confidence, entropy), then applied to the target. Validated against both a null (must give ≈ 0.5) and an injected-leakage case; both are permanent tests.

Stated plainly: a loss-threshold attack is a lower bound on leakage, not a ceiling. A flat curve is evidence for this attack family, not proof that no attack exists. The formal ε bound is the real guarantee.

Hardware

NVIDIA GeForce RTX 4050 Laptop GPU (6 GB VRAM), Windows 11, 16 GB RAM. CUDA 12.4. A median DP run takes 193 s; the full 76-run study takes 180 minutes of GPU time.

Hardware-forced constraint: batch size 32

Opacus materialises per-sample gradients, and this 6 GB card out-of-memory at batch 64. Batch 32 is therefore mandatory for DP arms; non-private arms use the same size so the comparison is clean. Two further facts were established experimentally and are documented in src/train.py:

  • PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True is not supported on this Windows build (PyTorch warns and ignores it).
  • Ghost clipping (grad_sample_mode="ghost") is the stable path: 0.24 GB live vs 7.8 GB for hooks mode, and not slower (123 vs 135 ms/step).

Measurement floor. The test split has only 234 minority images, so one image moves recall by 0.43 points and the binomial standard error at recall 0.70 is ±3.0 points. Every delta is read against that floor rather than treated as an effect by default.

Finding 1 — the guarantee is empirically real

MIA AUC on the non-private model is 0.634; it falls to 0.596 at ε = 1 and stays in a narrow band up to ε = 8. The drop is large relative to its seed spread (≈0.004), so this is the result the project can defend at three seeds. Above ε = 1 the curve is essentially flat: the guarantee bites once, and tightening further does not remove materially more measured leakage.

Finding 2 — class weighting helps; pretrained init backfires

At ε = 3, against vanilla's 0.685: class weighting reaches 0.735 (+0.050), pretrained init falls to 0.652 (-0.033), and the combination reaches 0.741 (+0.056). Class weighting moved minority recall in the same direction at every seed; pretrained init was worse than vanilla at every seed at ε = 8 despite being the strongest arm without DP.

Finding 3 — the fairness effect is present at ε = 1 but not monotone

Without DP the majority–minority gap is 0.262. At ε = 1 it widens to 0.287, the largest of any budget. It does not widen monotonically: by ε = 8 it is 0.236, below the no-DP value. So "tighter privacy is always less fair" is false on this benchmark — and the ε = 1 magnitude is within the ±3-point floor in any case. Reported as suggestive, not established.

Imbalance sweep

The native split is 2.88:1. We additionally trained on a balanced (1:1) and a severe (8:1) training set, holding the minority examples fixed and only shrinking the majority pool, 2 seeds per cell. At 8:1 the unweighted model recalls 0.622 of minority scans, down from 0.726 at 1:1, while the class-weighted model holds 0.729. This is the clearest evidence that a privacy-neutral loss change protects the minority exactly where imbalance is worst.

09Limitations and ethical considerations

  • Three seeds. Differences smaller than the ±3-point binomial floor are called noise, not findings. Paired, seed-matched deltas are in results/tables/paired_deltas.csv so a consistent small effect is distinguishable from one lucky run.
  • 28×28 inputs. MedMNIST downsamples from up to 384×2,916. Some diagnostic detail is destroyed at 28 pixels; results describe this benchmark, not full-resolution radiology.
  • Weak attack. Loss-threshold MIA is a lower bound on leakage. A flat curve is evidence for this attack family, not proof that no attack exists.
  • secure_mode off. Noise came from a fast PRNG. Standard for experimentation; a production claim would require secure mode and is not made here.
  • Batch size 32, forced by hardware. Larger batches would require more noise for the same ε; all arms share 32, so the comparison is internally valid.
  • One architecture, one dataset family. No claim that DP-SGD is unfair in general.
  • Data ethics. Public, de-identified datasets; no new patient data collected; no clinical deployment claimed — this is a study of a mechanism, not a validated diagnostic tool.

10Reproducing the project

First-time setup

cd DP-SGD-Medical-Privacy
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
.venv/Scripts/python.exe -m pip install -r requirements.txt

Run the study

bash scripts/run_grid.sh all        # 76 runs, resumable, one process per run
.venv/Scripts/python.exe -m src.analyze             # tables, figures, RESULTS.md
.venv/Scripts/python.exe -m src.make_final_report   # FINAL_REPORT.docx
.venv/Scripts/python.exe -m src.make_deck           # PRESENTATION.pptx

Runs are idempotent and resumable: each is keyed by a hash of its config, so re-running skips completed work. --force reruns; --list prints everything on disk.

Verify the invariants

.venv/Scripts/python.exe -m pytest tests -q     # 22 tests

The tests pin properties that would silently corrupt results if broken: class weights must favour the minority, imbalance construction must leave minority rows byte-identical, the MIA must return chance under a null and detect injected leakage, the DP accountant must spend the budget it claims, the model must contain no BatchNorm, and the multilabel weighted loss must keep its shape.

Artifact schema

Every run writes one JSON file recording: the full config, achieved ε, noise multiplier, clipping norm, steps run, parameter count, wall time, the per-epoch history, the per-seed metrics, and the data counts. Any number in any document can be traced back to the file that produced it.

11Running the live version

This page is the live version — a single self-contained HTML file with all figures embedded and all 76 runs loaded into the explorer. It needs no network after download.

Option A — open the file (simplest)

Double-click docs/guidebook/index.html. Everything works, including the filter/sort explorer, because there are no external requests.

Option B — serve it on a local URL (recommended for presenting)

.venv/Scripts/python.exe scripts/serve_guidebook.py
# then open http://127.0.0.1:8000

Serving it means the address bar holds a real URL you can put in a slide, and the print/PDF path behaves like a normal website. The server binds to localhost only.

Option C — publish it publicly with GitHub Pages

This must be done from your GitHub account, since it publishes to the internet.

  1. Create a repository (see the submission checklist for the exact git commands).
  2. Push the project, including docs/guidebook/index.html.
  3. In the repo: Settings → Pages → Source: Deploy from a branch → Branch: main, folder /docs → Save.
  4. GitHub builds it and gives you a URL of the form address beginning https://, then your GitHub username, then .github.io/dp-sgd-chest-xray-fairness/guidebook/. Settings → Pages shows the exact URL once it is live.

Before publishing, decide whether you want the repository public. A public repo exposes the author's name and code; the datasets are not included (data/ is gitignored) so no clinical images are redistributed.
